## D. 「共 250g」到底是「都要」还是「选一个」

**CX-068 云南卷粉 / 凉米皮**

原文:
```
胡萝卜[carrot]/黄瓜[cucumber]/海带[kelp]/折耳根[houttuynia]/绿豆芽[mung_bean_sprout] 共250g 配
```

现在:
```
胡萝卜[carrot] 或 黄瓜[cucumber] 或 海带[kelp] 或 折耳根[houttuynia] 或 绿豆芽[mung_bean_sprout] 共250g 配
```

**「共」这个字说明原作者的意思是「这几样加起来 250g」,也就是「且」**。但按「且」拆的话要给 5 个克数,我又得猜 5 个比例(比 C 组更没谱)。按「或」写则变成「任选一样 250g」,采购上是安全的(不会少买),语义上损失了「拌几样」的意思。

我选了「或」并**保留了「共250g」三个字**,这样原始信息没丢。但严格说「或 + 共」是矛盾的写法。

**需要定**:改成 5 项各 50g?还是接受「或」并把「共」删掉?

## G. 朴素解析器会读错的名称(没改,提醒)

`名称[id]` 这个格式假定名称里没有括号。全库有 **11 处**名称带括号或空格,一个只做 `^(.*?)\[` 匹配的解析器会把括号也吃进名称里:

| 名称 | 出现处 | 严重度 |
|---|---|---|
| `花椒水(花椒[sichuan_pepper]现泡)` | BF-045 · BF-047 | ⚠️ **最麻烦的一个** —— `[id]` 嵌在括号**里面**,解析出的名称是「花椒水(花椒」。这是 04 文件按 SPEC「中间物拆成原料」有意写的,它自己的附录也记了,所以我没动 |
| `鹰嘴豆(熟)` `白芸豆(熟)` `红腰豆(熟)` | XS-031 · XS-043 · XS-049 | 低 —— 括号在 `[id]` 前面,截断即可 |
| `鸡胸(片开拍薄)` `鸡胸(手撕)` | XS-034 · XS-052 | 低 |
| `外婆菜(袋装)` `干豆腐(千张)` `生鸡蛋(蘸)` `面粉(冰花水)` `春酱(韩式黑豆酱)` | CX-043 · BF-077 · RH-013 · RH-038 · RH-064 | 低 |

**建议**:SPEC 里补一句「名称部分不得含括号,加工状态/备注写到 `备注` 列」,然后统一清一遍。这次没做,因为属于改内容不是改格式。
