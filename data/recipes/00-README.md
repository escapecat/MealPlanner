# 菜谱库

**这是一个通用库,不针对任何特定用户。** 个人忌口、厨具、调料、辣度、耗时、难度、份数全部是**运行时的过滤/缩放配置**,不是收录边界。

所以库里包含内脏、苦瓜、秋葵、折耳根、有刺鱼、生腌、重辣、需要 30 天的酸菜、难度 5 的酒楼手艺 —— 它们该不该出现在你的餐桌上,由配置决定,不由库决定。

### 食材列引用字典

```
五花肉[pork_belly] 180g 主 · 红薯[sweet_potato] 150g 配 · 大米[rice] 80g 主食
```

角色:`主` / `配` / `主食` / `香料`。字典在 `../ingredients/`(601 条)。

**「或」关系**用 ` 或 `:`干鲍[dried_abalone] 或 干贝[dried_scallop] 15g 配`

> ⚠️ 曾经用 `|`,踩了坑 —— 它是 markdown 的列分隔符,写进单元格会把整行撑破。`05-西式` 因此损坏过 21 行。详见 `SPEC.md`。

**没有克数的**写 `适量`,不编数字。语义:要买,但不参与克数累加和包装规格计算。

### 厨具分两列

- `厨具必需` 用 ` + `(且):`炒锅 + 蒸架`
- `厨具可替代` 用 ` 或 `(或):`烤箱 或 空气炸锅`

原来混在一列用 `/` 和 `+`,程序分不出「或」和「且」。

### `type`

`dish` 一顿饭的组成部分 · `prep` 预制配料(做完进库存供别的菜引用)· `both`

`prep` 已经形成闭环:`家常红油 CX-022` · `复制酱油 CX-023` · `糍粑辣椒 CX-024` · `泡菜坛 CX-025` · `东北酸菜 BF-005` · `韩式泡菜 RH-050` · 三种高汤 · 葱油 · 卤水 —— 这些同时是别的菜的调料。

**「解锁一个味型」因此从「花钱买」变成了「花钱买 或 花时间做」。**

### 「活跃分钟」和「总分钟」为什么分开

红烧肉总共 80 分钟,其中 55 分钟在焖,人不用在厨房。一个是**我有多少时间**,一个是**我愿意花多少精力**。

只有一个字段的话,腊八蒜要么标 15(骗人)要么标 10080(吓跑人)。库里的极端值:

| 菜 | 活跃 | 总 |
|---|---|---|
| 自腌东北酸菜 | 30 分钟 | **20 天** |
| 腊八蒜 | 15 分钟 | **10 天** |
| 韩式酱蟹 | — | **4 天** |
| 醉蟹 / 四川泡菜 / 手作辣白菜 | 20-60 分钟 | **3 天** |
| 杭式酱鸭 | 30 分钟 | **25 小时** |

## 改造历史与踩过的坑

### 「两列重复」—— 会让采购量翻倍

原表的 `额外调料` 列里混进了大量其实是**食材**的东西。五路 agent 独立踩到,合计清理 **48+ 处**:花生米 · 粉条 · 干木耳 · 腊肠 · 紫菜 · 鸡蛋 · 面粉 · 马苏里拉 · 玉米饼 · 法棍 · 核桃 · 昆布 · 米纸 · 虾米……

**同一样东西出现在两列,采购量直接翻倍。** 现在的规则:`调料` 列只放调味料,食材一律只进 `食材` 列。

### 鲜香料曾经完全不会被买到

`06` 那路发现 **香茅 · 南姜 · 柠檬叶 · 青柠 有 24 处只存在于「额外调料」列**。留在那儿的话采购清单根本不列它们 —— 到店不会买,回家做冬阴功才发现没有。

同类问题:大量菜**菜名叫「蒜蓉XX」「葱爆XX」,但三列里根本没写蒜姜葱**。已按「菜名明说 / 备注明说 / 做法必然」三档补录,各文件末尾有 `## 本次补录的香料` 可复核。

一度有多个 agent 并发重写同一批文件,`02` 被截断到 60 道、`06` 到 32 道。已全部恢复。

## ⚠️ 全库未验证

**所有克数、耗时、难度都是估计值,没有一道实际做过并称量过。** `verified: false`

求解器要精确算「剩余量」,输入不准的话算出来的「零浪费」是假的。

同理 `../packages.md` 的包装规格 **99.3% 未经原文核实**(A 级只有 1 条)。所以「默认值 + 用户就地编辑」不是锦上添花,是这一层能不能用的前提。
