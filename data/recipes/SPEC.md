# 菜谱表格式规范 v2

> 本次改造把三件事合并成**一次重写**:字段重构 + 食材改引用 + 编号统一。
> 分两趟做等于把 530 行白写一遍,所以一次到位。

## 目标表头

```
| ID | 菜名 | 食材 | 做法 | 味型 | 辣度 | 活跃分钟 | 总分钟 | 难度 | 提前准备 | 锅数 | 厨具必需 | 厨具可替代 | 调料 | 跨顿 | type | 生食 | 备注 |
```

18 列。相对旧表的变化:

| 变化 | 说明 |
|---|---|
| `主料` + `配菜` → **`食材`** | 合并成一列。区分是主观的,各文件已经不一致 |
| 食材文本 → **`名称[id] 克数 角色`** | 引用食材字典 |
| `额外调料` → **`调料`** | 改成**全量**。「额外」是用户配置不是菜的属性 |
| `厨具` → **`厨具必需`** + **`厨具可替代`** | 原来 `/` 和 `+` 混用,程序分不出「或」和「且」 |
| `#` 数字编号 → **`XX-001`** | 文件内局部编号,加前缀 |

## 各列写法

### `ID`

文件内局部编号,补零三位:

| 文件 | 前缀 |
|---|---|
| `01-家常基础.md` | `JC-` |
| `02-川湘云贵.md` | `CX-` |
| `03-粤浙闽.md` | `YZ-` |
| `04-北方家常.md` | `BF-` |
| `05-西式.md` | `XS-` |
| `06-日韩东南亚.md` | `RH-` |

**已经是这个格式的不要重排。** 只有 `01-家常基础.md` 需要从 `1`-`121` 改成 `JC-001`-`JC-121`,顺序保持不变。

### `食材`

格式:`中文名[ingredient_id] 克数 角色`,多项用 ` · ` 分隔。

```
五花肉[pork_belly] 180g 主 · 红薯[sweet_potato] 150g 配 · 大米[rice] 80g 主食
```

**角色**取值:`主` `配` `主食` `香料`

- `主` —— 提供主要蛋白或构成这道菜身份的食材
- `配` —— 配菜、辅料
- `主食` —— 米面等碳水主体
- `香料` —— 蒜姜葱、香菜、紫苏这类提味的鲜料(注意:干香料属于 `调料` 列,不在这里)

#### 「或」关系:同一个位置多选一

有些菜的某个食材位是可替换的(`干鲍/干贝`、`草鱼/黑鱼`、`菠菜/油麦菜/小白菜`)。用 ` 或 ` 表示:

```
干鲍[dried_abalone] 或 干贝[dried_scallop] 15g 配
```

克数和角色写在整组的最后,对组内所有选项生效。

> ⚠️ **为什么不用 `|`** —— 这是踩过的坑,别再改回去。
>
> `|` 是 markdown 表格的列分隔符。单元格里写裸 `|`,那一行会**多出一列**,后面的做法、味型、辣度……全部整体右移,变成坏数据。
> `05-西式.md` 曾因此损坏 21 行,而 agent 自检还报告「每行都是 18 列」—— 因为它数的是分割后的结果。
>
> 转义成 `\|` 虽然能渲染对,但**没有任何机制能防止下一个 agent 忘记转义**。换一个天然不冲突的分隔符才是根治。

**`厨具可替代` 列同样用 ` 或 `**:

```
烤箱 或 空气炸锅
```

**`厨具必需` 用 ` + `**(且关系),两者语义不同不要混:

```
炒锅 + 蒸架        ← 两样都要
烤箱 或 空气炸锅    ← 二选一
```

#### 蒜姜葱必须写出来

菜名或备注里提到蒜蓉/蒜香/姜葱/葱爆/蒜泥的,**食材列必须有对应条目**,哪怕原表三列都没写。

理由:蒜姜葱在设计里是「每周现买的鲜料」不算囤货,**不写进食材列 → 不进采购清单 → 到店没买 → 做菜时才发现**。

补录范围,按这三档,**宁可漏不要瞎加**:
- 菜名里明说的(蒜蓉西兰花、姜葱爆猪肝、葱爆羊肉)
- 备注里明说的(「蒜末用热油激香」「葱姜垫底」)
- 做法上必然要用的(爆炒类基本都要蒜末炝锅)

参考克数:蒜 10-20g · 姜 10-15g · 小葱 10-15g,按菜的体量给。

补录的要在文件末尾单列一节 `## 本次补录的香料`,方便复核。

#### ⚠️ 食材不要在 `调料` 列重复出现

原表的 `额外调料` 列里混进了不少**其实是食材**的东西(花生米、粉条、干木耳、腊肠、紫菜、澄面、地瓜粉、燕皮、干香菇……)。

**这些一律只放进 `食材` 列,不要在 `调料` 列再写一遍。**

同一样东西出现在两列,**采购量会直接翻倍** —— 这是会真出错的 bug。

`调料` 列只放调味料:盐、酱油、醋、酒、糖、油、酱类、干香料、淀粉。

**id 从这三个字典里查**:
- `../ingredients/01-动物性.md`
- `../ingredients/02-蔬菜菌菇水果.md`
- `../ingredients/03-主食干货调料.md`

字典的 `别名` 列已经做过归一,先查别名再查名称。

⚠️ **匹配不上的不要硬猜、不要编 id。** 保留原文并在 id 位置写 `[?]`,同时记进未匹配报告。

#### `适量`:没有克数时的标准写法

有些食材原文就没给克数(海苔丝、昆布、虾片、紫菜这类),**不要编数字**,统一写 `适量`:

```
海苔丝[nori_shreds] 适量 香料
```

**语义**:这样东西**要买**,但用量不影响采购决策。

求解器的处理方式:进采购清单(否则你不会买),但**不参与克数累加和包装规格计算**。对海苔昆布这类「买一包吃很久」的东西,这个语义是准确的 —— 它们本来就不该按克算。

⚠️ 不要滥用。**主料和主要配菜必须有克数**,`适量` 只给真正的点缀类。

#### 备注可以补,但只能补「不补就会丢失的信息」

原则仍是不改备注。**唯一的例外**:某个信息原本只存在于被删掉的列里,删了就没了。

实例:`RH-041/047/056` 的「泡菜汁」和「熟成泡菜」是同一个 id,按去重规则必须从 `调料` 列删掉一份 —— 但「泡菜汁一起倒进去」这个做法要点会随之消失。这种情况**把信息并进备注**是对的。

补的时候要标注是补录的,方便复核。

⚠️ **克数缺失的保留原样**(比如「少许」「1 根」),不要瞎补数字。

### `调料`

**全量**列出,不再是「超出启动包的部分」。格式同上,克数可省:

```
盐[salt] · 生抽[light_soy] · 郫县豆瓣[doubanjiang] 15g · 花椒[sichuan_pepper] 3g
```

原表 `额外调料` 列里的内容全部保留并加 id,**另外补上那些原来因为「属于基础 11 样」而没写的**:盐 · 生抽 · 蚝油 · 白砂糖 · 白胡椒粉 · 食用油 · 玉米淀粉 · 料酒 · 孜然粉 · 黑胡椒 · 芝麻油。

按这道菜实际会用到的补,不是每道都把 11 样全填上 —— 清炒时蔬不需要孜然粉。

### `厨具必需` / `厨具可替代`

- **`厨具必需`** —— 且关系,多个用 ` + `。例:`炒锅 + 蒸架`
- **`厨具可替代`** —— 或关系,一组内用 ` | `,多组用 ` · `。例:`烤箱 | 空气炸锅`

原表 `厨具` 列里:
- 写 `A + B` 的 → 全进 `厨具必需`
- 写 `A/B` 的 → 判断语义。多数是「二选一」→ 进 `厨具可替代`
- 只有一个的 → 进 `厨具必需`,`厨具可替代` 填 `—`

⚠️ **`烤箱/空气炸锅` 的替代不是等价的。** 如果原备注提到需要调整温度或时间,在 `备注` 里保留这条信息。

### 其余列

`菜名` `做法` `味型` `辣度` `活跃分钟` `总分钟` `难度` `提前准备` `锅数` `跨顿` `type` `生食` `备注` —— **内容原样照搬,不要改**。

原表没有 `type` 或 `生食` 列的(部分文件),按下面规则补:
- `type`:绝大多数是 `dish`;做完进库存供别的菜引用的是 `prep`(泡菜、卤水、红油、高汤、腌菜);两者皆可的是 `both`
- `生食`:寿司、刺身、生腌、生拌标 `是`,其余 `否`

## 硬性要求

1. **道数一个都不能少。** 改之前先数一遍原文件的道数,改完再数一遍,写在回复里
2. **只改格式和引用,不改菜的内容。** 克数、耗时、难度、备注这些数值不要"顺手优化"
3. **表格后原有的 `## 统计` 一节保留**,数字按新表重算
4. **未匹配的食材**追加到文件末尾一节 `## 未匹配食材`,列出:原文写法 · 出现在哪几道菜 · 你判断它该归哪个字典。这一节是给人看的待办,不是失败标记

## 已知的坑

- **`天贝`** 目前错放在 `01-动物性.md`(它是大豆发酵品),id 照用,以后会迁到豆制品字典
- **`甜酱油`** 在库里是两样东西:云南甜酱油 和 印尼 kecap manis,字典里已拆成两条,别用错
- **干货和鲜货是不同条目**,克数不可换算(干香菇 20g ≈ 鲜香菇 100g)。原文写「干香菇」就查干香菇的 id
- **中间物不在字典里**:蒜末、姜泥、苹果泥、花椒水、淘米水、面粉油酥 —— 这些是现做的,不是采购项。遇到就换成它的原料(蒜末 → 蒜),或者归进 `调料` 列的备注
